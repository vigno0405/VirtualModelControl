# How it works

## The idea

Virtual Model Control replaces abstract gains with physical elements placed on the robot. To
hold a fingertip at a point, you attach a virtual spring between the fingertip and the point; to
keep an arm away from an obstacle, you attach a repulsive spring around the obstacle; to calm a
motion, you attach a damper. The controller computes the forces these elements would produce,
and the motors apply them.

Because the elements are physical, the controller is easy to read (every number has a unit and
a place) and it behaves well: a set of springs and dampers stores or dissipates energy, so it
cannot make a passive robot unstable.

## Four steps

```{mermaid}
flowchart LR
    A["1. Robot<br/>model + masses<br/>robots.helyx.arm()"] --> C
    B["2. Controller<br/>virtual springs,<br/>dampers, masses"] --> C
    C["3. compile()<br/>CasADi functions<br/>(about 20 µs per step)"] --> D
    D["4. VMCController.step()<br/>motor angles in,<br/>motor torques out"]
    D -->|torques| E["real robot or<br/>simulator (Plant)"]
    E -->|motor angles, rates| D
```

1. **Describe the robot.** A *robot mechanism* holds a kinematic model (where every point of
   the robot is, as a function of its configuration), how the motors drive it (tendons,
   couplings), and its physical components (masses, stiffness, gravity). Templates for the lab's
   robots are ready in `virtualmodelcontrol.robots`.
2. **Describe the controller.** A *virtual mechanism* holds the elements you place: springs,
   dampers, inertances and force sources, each acting on a *coordinate* (a point of the robot, a
   joint angle, the distance between two points, a projection on a direction...).
3. **Compile.** `vmc.compile` builds one CasADi function from both mechanisms: the forces of
   every element, mapped to motor torques through exact Jacobians.
4. **Run.** `vmc.VMCController` evaluates the function at each control step. The same
   controller runs on a simulator (`vmc.sim.ModelPlant`) or on the hardware.

## What the library adds

- **Exact derivatives everywhere.** Jacobians, Hessians and the robot's dynamics are generated by
  automatic differentiation from one model; nothing is derived by hand.
- **Everything is a parameter.** Gains, goals, attachment points and every geometric number
  (rest lengths, tendon angles, joint axes, mounting poses) are `Param` objects with units, so the
  same model serves control, calibration and design.
- **Energy is accounted for.** The compiled controller reports its stored energy, its dissipation
  and the power it exchanges with the robot; changing a gain while running returns the exact
  energy jump.
- **One run loop for simulation and hardware**, with a guard that sends zero torque when a
  reading is missing or invalid.
